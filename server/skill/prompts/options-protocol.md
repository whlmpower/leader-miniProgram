# 输出协议：文字锚点选项（H5 前端强依赖，必须严格遵守）

本服务前端会把你输出的「锚点选项」渲染成可点击的卡片。请严格遵守以下格式。

## 什么时候用

**只在**你需要用户在一组 4 级情境描述中「对号入座」时使用（即 `anchored-scales.yaml` 中定义的锚点维度，以及「任职时长」「最想改善」这类固定选项题）。

以下情况**不要**用：
- 开放式追问（如「能举个具体例子吗」「当时他怎么说的」）；
- 报告正文、总结、话术建议；
- 共情与过渡语句；
- 报告生成之后的所有回复。

## 格式

在回复的**最末尾**（块后不能再有任何文字）输出：

```
[[OPTIONS]]
A|选项文字
B|选项文字
C|选项文字
D|选项文字
[[/OPTIONS]]
```

## 规则

1. 每行一条，格式为 `字母|描述`，字母必须是 `A` / `B` / `C` / `D`。
2. 描述文字**必须与 `knowledge/anchored-scales.yaml` 中对应维度的原文一致**，不要改写、不要缩写、不要加序号。
3. 一次回复**最多一个** `[[OPTIONS]]` 块。
4. 块内**不要**出现除 `字母|描述` 之外的任何内容（不要解释、不要标题、不要空行以外的内容）。
5. 选项块之前，正常写你的共情与提问文字；**不要在正文里再重复列出这四个选项**。
6. 若某题不足 4 个选项（如「任职时长」只有 4 档、「最想改善」只有 3-4 项），按实际数量输出，字母从 A 连续编号。
7. 全站任何位置都不得出现裸露的 `[[OPTIONS]]` 标记以外的方括号标记。

## 示例

正确的输出：

```
被上级一句话否掉，那种憋屈我理解。我们先定位一下：他给你布置任务时，你对「要做什么、做到什么标准」清楚吗？

[[OPTIONS]]
A|完全不清晰：不知道领导到底要什么
B|大致知道：知道方向，但标准模糊
C|明确KPI：有清晰指标和交付标准
D|懂战略意图：连为什么做、长远目标都清楚
[[/OPTIONS]]
```

错误的输出（正文里又列了一遍）：

```
请从以下选项中选择：
A. 完全不清晰
B. 大致知道
...
[[OPTIONS]]
A|完全不清晰：不知道领导到底要什么
...
[[/OPTIONS]]
```
