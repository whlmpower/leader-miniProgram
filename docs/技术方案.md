## 3. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Node.js 22 + Express | 基线已用，生态成熟 |
| 密码哈希 | Node 内置 `crypto.scrypt` | 零依赖，避免 bcrypt 原生编译 |
| JWT | 内置 `crypto` 手写 HS256 | 零依赖，够用且可控 |
| 验证码 | 自研 SVG 生成（无图像库） | 轻量、可控 |
| 模型 | StepFun `step-3.7-flash`（OpenAI 兼容） | 中文友好 |
| 配置 | `dotenv` 载入 `server/.env` | 密钥走环境变量 |
| 前端 | 原生 H5（HTML/CSS/JS），无构建 | 与后端解耦，便于迁小程序 |
| Markdown | `marked` + `DOMPurify`（前端 vendor 与后端共用） | 前后端渲染效果一致 |
| 存储 | JSON 文件（fs 同步写） | 数据量小、24h 删除，零运维 |

## 5. 数据模型

### 5.1 用户 `data/users.json`

```json
{
  "users": [
    {
      "phone": "13800000000",
      "pwdHash": "<scrypt_hex>",
      "pwdSalt": "<hex>",
      "createdAt": 1727000000000,
      "expiresAt": 1727086400000,
      "usedAt": null,
      "revoked": false
    }
  ],
  "admin": { "phone": "13900000000", "pwdHash": "<hex>", "pwdSalt": "<hex>" }
}
```

状态计算：`revoked` → 已作废；`usedAt===null` 且未过期 → 未使用；`usedAt!==null` → 已使用；`now>expiresAt` → 已过期。admin 无 `expiresAt`。

### 5.2 会话 `data/sessions/<id>.json`

```json
{
  "id": "uuid",
  "phone": "13800000000",
  "createdAt": 1727000000000,
  "status": "collecting",
  "pack": "generic",
  "messages": [{ "role": "assistant", "content": "...", "ts": 1727000000000 }],
  "report": { "markdown": "...", "html": "...", "generatedAt": 1727000000000 },
  "postReportTurns": 0,
  "conversationFile": null,
  "conversationReady": false
}
```

> `pack` 为会话创建时的行业包快照，避免中途改配置导致话术漂移。

## 6. 核心模块设计

### 6.1 skillLoader（重写）

装配顺序：

1. `SKILL.md` —— 角色、流程、边界、深度分层、输出模板
2. `knowledge/` —— `anchored-scales.yaml`（4 级文字锚点）、`diagnosis-rules.yaml`（理论匹配 + `required_anchors`）、`action-templates.md`、`learning-paths.md`
3. `references/` —— 情境领导力、管理方格、GROW、向上管理、横向协作
4. `industry-packs/<pack>/` —— 目录下所有 `.md` / `.yaml` 全量拼入
5. `prompts/` —— `options-protocol.md`（锚点输出协议）、`report-template.md`（报告指令）
6. 运行时约定段

结果缓存在 `cachedPrompt`，避免每次请求读盘。

### 6.2 锚点选项协议（本方案核心新增）

**问题**：Skill 要求「禁止打分，只用 4 级情境描述」，但纯文本选项在手机上输入成本高。

**方案**：约定一个轻量标记协议，模型在回复末尾输出：

```
[[OPTIONS]]
A|完全不清晰：不知道领导到底要什么
B|大致知道：知道方向，但标准模糊
C|明确KPI：有清晰指标和交付标准
D|懂战略意图：连为什么做、长远目标都清楚
[[/OPTIONS]]
```

- **解析**：前端 `app.js#splitOptions` 正则提取，渲染为选项卡片；正文部分单独渲染。
- **作答**：点击后以 `选 A：描述` 作为用户输入发送，模型易识别。
- **退化**：若模型未输出该块，前端直接展示文本 + 保留输入框，体验无损。
- **落盘**：`options.js#stripOptions` 在生成 HTML 前把块转成 Markdown 列表，避免用户看到标记。
- **约束写入提示词**：`prompts/options-protocol.md` 明确规定了何时用、格式、选项文字必须与 `anchored-scales.yaml` 原文一致、块必须在末尾。

### 6.3 报告生成

- 调用 `buildReportInstruction()`（报告模板 + 当前行业包语境），`temperature: 0.6`。
- 模板见 `skill/prompts/report-template.md`，覆盖：问题定位 / 理论依据 / 根因分析 / 行动清单（立即做·本周做·跟进指标·避坑）/ 预期效果 / 置信度拆解 / 诊断依据 / 理论延伸。
- 硬性要求：必须基于对话具体案例；话术写成可照读的完整句；触及心理/价值观边界须显式声明。

### 6.4 对话整理 HTML（下载产物）

- 用户回复「需要」时触发生成，`resolvePostReportReply` 关键词拦截，**不调用 LLM**（避免输出 HTML 源码噪音）。
- 内容 = 报告生成前的全部消息 + 报告消息（标记为「诊断报告」高亮）。
- **版式例外**：走浅底（打印友好），品牌识别由 6px 深墨蓝顶边 + 青绿强调承担。

### 6.5 跨平台写入（Windows 兼容）

`config.js` 导出 `WRITE_OPTS`：

```js
export const WRITE_OPTS = process.platform === 'win32' ? {} : { mode: 0o600 };
```

Windows 上对已存在文件设置 POSIX mode 会触发 chmod 并抛 `EPERM`，故 Windows 下不传。所有敏感文件写入统一使用。

## 7. API 接口设计

### 7.1 配置

- `GET /api/config` → `{ features:{ads:false}, maxInputChars, maxPostReportRounds, retentionHours, mock, pack }`

### 7.2 认证与账号

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/auth/captcha` | 无 | 获取图形验证码 `{captchaId, svg}` |
| POST | `/api/auth/login` | 无 | `{phone, captchaId, captchaInput, password}` → `{token, role}` |
| POST | `/api/auth/logout` | 无 | 清除 httpOnly Cookie |
| GET | `/api/me` | 任意 token | 返回 `{phone, role}` |

### 7.3 管理后台（`role=admin`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/users` | 创建用户并生成密码 |
| GET | `/api/admin/users` | 用户列表（含状态） |
| POST | `/api/admin/users/:phone/reset` | 重新生成密码 |
| POST | `/api/admin/users/:phone/revoke` | 作废账号 |
| PUT | `/api/admin/password` | admin 修改自身密码 |

### 7.4 诊断与会话（任意 token）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/sessions/mine` | 当前用户最近有效会话（刷新恢复） |
| POST | `/api/session` | 新建会话，返回 `sessionId` + 确定性开场白 |
| GET | `/api/session/:id` | 会话状态 + 历史 messages + reportHtml |
| POST | `/api/session/:id/message` | 发消息（≤1000 字）；返回 `{reply, conversationReady, conversationJustReady, postReportTurnsLeft}` |
| POST | `/api/session/:id/report` | 生成报告 → `{reportHtml, reportMarkdown, followup}` |
| GET | `/api/session/:id/conversation/download` | 下载对话整理 HTML |

### 7.5 错误码

| HTTP | 含义 |
|---|---|
| 400 | 参数缺失/格式错（手机号、字数超限） |
| 401 | 未登录 / token 失效 |
| 403 | 角色不足 / 报告后轮次用尽 |
| 404 | 会话/用户不存在 |
| 429 | 登录失败限流达上限 |
| 502 | 模型调用失败 |

## 8. 前端技术方案

### 8.1 路由与状态

单页五视图 `home / login / admin / chat / report`，通过 `data-view` + `is-active` 切换。全局状态集中在 `state`（role / sessionId / messages / pendingOptions / postReportTurnsLeft …）。启动时若有 token 调 `/api/me` 校验。

### 8.2 网络层 `api.js`

统一 `request()`：自动附加 `Authorization: Bearer`（token 的 localStorage 副本），`credentials: 'same-origin'`；401 时清理 token 并派发 `auth:expired` 事件。

### 8.3 设计 token（`tokens.css`）

```css
--bg: #14202E;  --bg-2: #1C2C3E;  --bg-3: #22354A;
--ink: #E8EEF4; --ink-2: #C4D2DF; --ink-3: #8BA0B5;
--accent: #35B89A; --accent-tint: rgba(53,184,154,.12);
--line: rgba(232,238,244,.12);
--serif: "Noto Serif SC"; --sans: "Noto Sans SC";
```

质感签名为 `body::before` 的极淡水平网格线（1px / 4px 周期），替代职业罗盘的宣纸噪点。

### 8.4 关键交互

- **选项卡片**：`#optArea` 容器，青绿边框；`.opt-key` 显示 A/B/C/D；点击后禁用全部项并发送；发送中/禁言时隐藏。
- **字数计数**：`input` 事件更新 `#charCount`，超限加 `.over`。
- **禁言**：`isMuted()` = 已报告 且 剩余轮次 ≤ 0 → 输入框与发送按钮禁用，placeholder 提示结束。
- **下载**：`conversationReady` 为 true 时显示按钮，点击跳 `downloadUrl`。

## 9. 安全设计要点

1. 密码 scrypt 哈希 + 随机 salt，明文不落盘，仅创建/重置时一次性返回。
2. JWT HS256 + 强随机 `JWT_SECRET`；httpOnly + SameSite=Lax Cookie，XSS 无法窃取。
3. 图形验证码服务端生成、绑定 captchaId、5min 过期、一次性消费（防重放），先校验再放行密码校验。
4. 限流：手机号(5) + IP(10) 双维度滑动窗口；仅手机号/密码错误计数。
5. 防枚举：登录失败统一提示「手机号或密码错误」。
6. 会话归属校验：非本人会话一律 404（不暴露存在性）。
7. 安全响应头：CSP / `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy`；production 下 HSTS + cookieSecure。
8. 隐私：对话/报告 24h 自动删；手机号掩码展示；`TRUST_PROXY` 未配置时不信任 XFF。

## 10. 部署方案

| 项 | 方案 |
|---|---|
| 主机 | 轻量云服务器（2C2G），**单实例常驻** |
| 反向代理 | Nginx：SSL 终止 + XFF + X-Real-IP |
| 进程管理 | pm2（`deploy/ecosystem.config.js`）或 systemd（`deploy/leader.service`） |
| 域名 | 已备案 HTTPS 域名；`TRUST_PROXY=loopback` |
| 端口 | 3002（与职业罗盘 3001 隔离）；生产建议 `LISTEN_HOST=127.0.0.1` |

`index.js` 已处理 PM2 下的 `isMain` 误判（以脚本真实位置解析 argv[1]，并用 `PM2_HOME` / `pm_id` 双保险），避免「pm2 online 但端口不监听」。
