## 2. 产品概述

### 2.1 产品定位

一款以「职场管理困境诊断」为核心的产品。用户通过一问一答式的对话，沿三个沟通方向与经典管理学理论，厘清困境的真实根因，最终得到一份**带可执行话术的结构化诊断报告**。

### 2.2 与职业罗盘的关系

| 维度 | 决策 |
|---|---|
| 交互 | **完全对齐**职业罗盘：首页 → 登录 → 一问一答 → 手动生成报告 → 下载 |
| 工程 | 后端模块（鉴权 / 限流 / 会话 / 报告）平移复用，端口 3002 隔离 |
| 视觉 | **刻意区分**：不用宣纸米白编辑风，改为石墨深蓝权威咨询风 |
| 诊断引擎 | 换成 `omni-leadership-advisor` Skill（三方向 + 文字锚点 + 理论匹配） |

### 2.3 目标用户

- **核心**：企业基层管理者与全体职场人，具体为——
  - 区县 / 地市 / 省公司职能员工：需**向上汇报 + 横向协调**；
  - 一线管理者：需**向下管理**。
- **准入**：封闭分发，账号由管理员统一创建并发放，不开放自助注册。

### 2.4 核心价值主张（首页唯一传达目标）

> **「这个网站能说清我卡在哪，而且给的话我明天就能用。」**

叙事闭环：三个方向撑「说清」、真实样例撑「能解决」、隐私条款撑「安全」。

### 2.5 对外文案原则（贯穿全站）

- **不暴露技术栈**：不向用户提及「大模型 / StepFun / API / 提示词」等字眼。
- 用户关心的三件事：靠不靠谱（理论）、对我有没有用（话术）、安不安全（隐私）。

## 3. 名词与角色

| 名词 | 说明 |
|---|---|
| 管理员（admin） | 系统初始预设账号，负责创建用户、生成密码、查看用户列表。密码长期有效 |
| 普通用户（user） | 由 admin 创建、线下发放账号密码，完成诊断与下载 |
| 图形验证码 | 登录页防机器验证码（SVG），与 admin 生成的「密码」是两种完全不同的东西 |
| 密码 | admin 为用户生成的 10 位凭证（1 位数字 + 9 位字母），登录成功后 24h 失效 |
| JWT | 登录成功后签发的无状态令牌，有效期 24h，存于 httpOnly Cookie |
| 锚点 | 4 级情境化文字描述，替代 1-5 分打分，用户选最贴近的一条 |
| 行业包 | 只换话术与语境的可插拔配置（`generic` / `postal`），不改理论骨架 |

## 4. 功能需求

### 4.1 账号与权限体系

- **账号来源**：仅管理员创建，无自助注册入口。
- **管理员初始凭据**：写入 `.env` 的 `ADMIN_PHONE` / `ADMIN_PASSWORD`，首次启动写入存储，可在后台修改。
- **密码生成规则**：10 位 = 1 位数字（随机位置）+ 9 位大小写字母；**排除歧义字符**（0/O、1/l/I）；**存储为哈希**（scrypt），绝不存明文。
- **生命周期**：登录成功后 24h 内可复用；超过 24h 自动失效，需 admin 重新生成。
- **下发方式**：admin 后台生成后页面展示 + 复制，线下（微信/口头）告知用户。MVP 不接短信/邮件。

### 4.2 登录认证（三要素）

- 要素：**手机号 + 图形验证码 + 密码**。
- **校验顺序**：先校验图形验证码（错则直接拦截）→ 再校验手机号 + 密码。
- **失败计数**：同一手机号 24h 内最多失败 5 次；同一 IP 24h 内最多失败 10 次；滑动窗口自动恢复。仅「手机号或密码错误」计入，图形验证码错误**只拦截本次、不计数**。
- **防枚举**：无论「手机号未注册」还是「密码错误」，统一提示「手机号或密码错误」。
- **登录页合规**：必须勾选同意《隐私协议》后方可登录（未勾选时按钮禁用）。

### 4.3 首页（公开）

首页无需登录即可查看全部内容；点「开始诊断」跳转登录。

信息架构：

1. **Hero**：主标题「职场里卡住的事，多半不是能力问题」+ 一句话承诺 + 三方向标签。
2. **01 诊断什么**：三个方向卡（向上 / 向下 / 横向），每张含**典型困境清单 + 对应理论**。撑「说清」。
3. **02 诊断样例**：真实链路脱敏样例卡（点开为 `web/samples/dialogue.html`），含用户原述、问卷作答、完整报告。撑「能解决」。
4. **03 怎么诊断**：对话而非填表 / **对号入座，不打分** / 约 10 分钟 / 24h 自动删除。撑「靠谱」。
5. **04 隐私与条款**：收集范围、不收集范围、留存期限、能力边界 + 协议入口。
6. **05 怎么开始**：说明封闭分发、账号由管理员发放。
7. **CTA**：「开始诊断」→ 登录。

### 4.4 诊断对话

- **权限**：需任意有效 JWT。
- **交互**：一问一答；AI 提问基于上一轮回答。
- **锚点题**：模型在回复末尾输出 `[[OPTIONS]]…[[/OPTIONS]]` 块，前端渲染为**可点击选项卡片**；点击后以「选 A：描述」发送。**输入框始终保留**，用户可直接打字，包括「2、3、4 都有」这类多选自述。
- **输入限制**：每轮 ≤ 1000 字符（前端实时计数）。
- **报告前**：不限轮次。
- **生成报告**：用户主动点按钮触发（非模型自动、非固定轮次），每次诊断仅一次。
- **报告后**：最多再追问 10 轮，用尽后禁言。
- **续聊**：刷新页面可恢复历史消息。

### 4.5 报告生成与下载

- **生成**：后端调用 StepFun 生成 Markdown，转为 HTML 落盘，报告页直接预览。
- **下载**：报告生成后 AI 追问是否需要整理；用户回复「需要」→ 后端生成**对话整理 HTML**（含完整对话 + 报告）；点「下载报告」保存。回复「不用」则跳过。
- **意图识别**：命中下载意图（需要/下载/整理/导出…）时后端直接拦截处理，不调用 LLM，避免输出无关话术。
- **留存**：报告生成后保留 24 小时供重复查看/下载，超时自动删除。

### 4.6 管理后台

- **权限**：接口要求 `role=admin`。
- **生成密码区**：输入手机号 → 生成 10 位密码 → 虚线框展示 + 复制按钮 → 线下发放。
- **用户列表**：手机号、密码状态（未使用 / 已使用 / 已过期 / 已作废）、操作（重新生成、作废）。
- **admin 自身**：可修改自己的密码。

### 4.7 隐私与数据安全

- 收集范围：手机号、账号密码（哈希存储）、对话内容。
- 不收集：通讯录、位置、设备标识；不接入第三方统计与广告 SDK。
- 留存：对话与报告 24h 自动删除；密码哈希存储，服务端不留存明文。
- 服务端每小时清理过期会话与报告文件。

## 6. 业务规则与约束汇总

| 规则 | 取值 |
|---|---|
| 密码长度 / 构成 | 10 位 = 1 数字 + 9 字母（排除 0/O/1/l/I） |
| 用户密码有效期 | 登录成功后 24h 自动失效 |
| admin 密码有效期 | 长期有效 |
| JWT 有效期 | 24h（httpOnly Cookie） |
| 失败限流 | 同手机号 24h≤5 次；同 IP 24h≤10 次 |
| 失败计数触发 | 仅手机号/密码错误（图形验证码错误不计数） |
| 每轮输入上限 | 1000 字符 |
| 报告前轮次 | 不限 |
| 报告后追问 | 最多 10 轮，之后禁言 |
| 数据留存 | 会话 + 报告 24h 自动删除；未报告会话 3 天清理 |
| 账号注册 | 封闭分发，仅 admin 创建 |
| 行业包 | `ACTIVE_PACK=generic`（默认）/ `postal`，会话创建时快照 |

## 7. 设计语言（石墨深蓝 · 权威咨询风）

| 维度 | 取值 |
|---|---|
| 气质 | 权威咨询风——像一份付费咨询报告，而非模板站 |
| 表面 | 深墨蓝 `--bg #14202E` / `--bg-2 #1C2C3E` / `--bg-3 #22354A` |
| 文字 | `--ink #E8EEF4` / `--ink-2 #C4D2DF` / `--ink-3 #8BA0B5` |
| 强调 | 青绿 `--accent #35B89A`（唯一锐利色，用于编号 / 印章 / 主按钮 / 选中态 / 报告小节标题） |
| 字体 | 标题与报告小节用衬线（Noto Serif SC），正文与 UI 用无衬线（Noto Sans SC） |
| 质感 | 极淡水平网格线（分析网格 / 坐标纸隐喻），替代职业罗盘的宣纸噪点 |
| 圆角 | 小圆角（4–10px），保留专业感 |
| 动效 | 仅入场错落淡入 + 轻量 hover；支持 `prefers-reduced-motion` |
| 记忆点 | 栏目编号 01/02/03、青绿「全」字方印、顶部 4–6px 品牌条 |

**五视图设计重点**：

1. 首页：三方向卡（青绿左边框 + 困境清单）、样例卡（hover 上浮）、细线栏目分隔。
2. 登录：三要素 + 协议勾选（未勾选禁用）+ 模糊错误提示 + 限流说明。
3. Admin：生成密码区（青绿虚线框）+ 细线用户列表（状态标签）。
4. 对话：AI 左深墨蓝卡片 / 用户右青绿实底；**锚点题渲染为选项卡片区**（青绿边框容器 + A/B/C/D 键标）；1000 字实时计数；报告后 10 轮倒计时禁言。
5. 报告预览：正式报告版式（衬线大标题 + 青绿小节标题 + 置信度表格 + 引用块），底部 24h 删除提示。

**下载文件例外**：下载的对话整理 HTML 走**浅底版式**（打印友好），品牌识别由深墨蓝顶边 + 青绿强调承担。

## 8. 验收标准

- [ ] 未登录访问诊断接口返回 401；admin 接口非 admin 角色返回 403。
- [ ] 图形验证码错误只拦截、不计数；手机号/密码错误计入限流。
- [ ] 同手机号失败 5 次被拒；同 IP 失败 10 次被拒；窗口滑动恢复。
- [ ] 未勾选隐私协议时「登录」按钮禁用。
- [ ] 用户密码登录后 24h 失效；admin 密码长期有效。
- [ ] 首页公开可浏览；首页文案不暴露技术栈。
- [ ] 锚点题渲染为可点击卡片；点击后正常推进；用户也可直接打字回答。
- [ ] 下载的 HTML 中不含裸露的 `[[OPTIONS]]` 标记。
- [ ] 诊断每轮 ≤1000 字；报告后最多 10 轮，第 11 轮禁言。
- [ ] 报告生成后回复「需要」可下载；24h 后对话 + 报告自动删除。
- [ ] Admin 可生成密码、查看用户列表（状态/过期）、重新生成/作废。
- [ ] 设计语言落地：深墨蓝底 + 青绿强调 + 衬线标题 + 网格纹理。

## 9. 风险与待办

1. **大模型 Key**：本地未配置 `LLM_API_KEY`，当前以 `LLM_MOCK=true` 演示兜底运行；拿到 Key 后填入 `.env` 并把 `LLM_MOCK` 改为 `false`。
2. **样例来源**：首页样例取自 `leader-process/outputs/全向领导力顾问_对话记录与优化观察.md`（真实链路，已脱敏、无姓名单位）。如需更换为其他真实记录，替换 `web/samples/dialogue.html` 内容即可。
3. **行业包内容深度**：`postal` 包目前只有语境文件，`generic` 包覆盖知识型/操作型/结果导向型团队；两者话术丰满度有待真实使用后迭代。
4. **锚点协议依赖模型稳定性**：若模型不按 `[[OPTIONS]]` 格式输出，前端会退化为纯文本展示（不会报错），但选项卡片体验会丢失。可考虑后续加"格式修复重试"。
5. **类目/合规风险**：管理咨询类内容在微信小程序个人主体大概率过审失败；H5 独立站可规避类目。若后续迁小程序，需办理个体工商户主体。
6. **JWT 无主动失效**：令牌泄漏 24h 内有效，高风险场景后期可加黑名单（本期不做）。
7. **存储形态约束**：JSON 方案依赖单实例常驻，勿用纯 Serverless 部署。
